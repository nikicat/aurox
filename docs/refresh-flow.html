aurox · every path that touches the network for package data

A fetch is never silent — and upgrade fetches on a TTL, not every time.

What you type (violet), the decisions aurox makes (diamonds), the engine steps (teal), the network work itself (amber), and every end state — the session's package data is current (green) or the command stopped (red).

The three properties. The one expensive thing here — the ~2 GiB bootstrap clone — is announced and consented to at a moment you can think about it, and which trigger asked decides whether it may even be offered. upgrade re-fetches only past refresh_max_age_secs (default 1 h); refresh is the always-fetch command. And the TTL stamp belongs to the AUR, so a repo-only refresh never suppresses an AUR fetch you still need.
